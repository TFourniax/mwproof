# Moat strategy

Aon, Marsh, Zurich or a well-funded software company can copy a dashboard. They must not be able to copy the asset behind it.

## 1. Planned-vs-actual infrastructure event ledger

The primary moat is a proprietary cross-project dataset linking promised milestones to observed outcomes: grid energisation, permits, transformer delivery, EPC completion, cooling commissioning, tenant readiness and operational capacity. Start with public European records; deepen with customer data under anonymised benchmarking rights.

## 2. Calibration, not prompts

The valuable IP is the calibrated probability distributions and dependency structure by country, utility, OEM, equipment class, EPC profile and project archetype. Prompt engineering is not a barrier.

## 3. Evidence network

ProofMW should progressively ingest signed attestations or API evidence from utilities, OEMs, EPCs, insurers and operators. Direct verification is harder to recreate than scraped information.

## 4. Contract embedding

The strongest switching cost appears when financing/insurance documents reference ProofMW outputs or data requirements: e.g. reporting covenants based on verified capacity milestones. This is a long-term goal, not a V1 claim.

## 5. Independence

Large brokers have distribution and risk expertise but can simultaneously advise, place insurance and serve multiple stakeholders. ProofMW should preserve a narrow independent-verification identity and make every output traceable.

## 6. AIRS as open schema, models/data proprietary

Open the interchange format to reduce integration friction. Keep benchmark data, calibration models and cross-project outcome history proprietary.

## Immediate moat-building action

Build a Europe Public Infrastructure Graph covering projects, planning records, environmental decisions, grid/interconnection announcements, OEM evidence, financing events and actual commissioning dates. Every public planned-vs-actual pair is future calibration data.
