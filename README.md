# ProofMW

**Evidence-first underwriting infrastructure for AI/data-center delivery risk.**

ProofMW reconstructs what developers, utilities, regulators, OEMs and other primary sources said **at the time**, preserves revisions and contradictions, maps physical delivery dependencies, and only then evaluates what probabilistic statements the evidence can support.

> **Current product mode: `EVIDENCE_ONLY`.** The service is runnable and decision-useful, but model confidence levels remain blocked by explicit model-risk gates until enough out-of-time evidence exists. ProofMW does not manufacture a P90/P95 because a UI would look better with one.

## What V0.5 adds

- A dated, hashed **Coverage Snapshot** instead of an unverifiable claim that the public dataset is “complete”.
- A leakage-safe **conditional schedule benchmark** that must beat developer dates and a global historical median out of time before it can influence underwriting.
- A local, disposable **SQLite serving index** while append-only JSON remains canonical.
- A lender-facing **Decision Card** that surfaces evidence, conflicts, physical gaps and next diligence requests without fabricating an approve/decline score.
- A cached FastAPI serving layer with `/ready`, search, snapshots, benchmark and decision-card endpoints.
- Container packaging plus end-to-end HTTP and Docker smoke tests in CI.
- Additional primary-source histories for atNorth, Bulk Infrastructure, maincubes and VIRTUS, including retrospective evidence and source contradictions that are preserved rather than overwritten.
- Reproducibility artifacts generated by CI for every build.

## Why the data model matters

A normal market database tends to keep the latest state: “RFS 2028”. ProofMW keeps the **claim history**:

`forecast → revised forecast → conflict → physical milestone → actual outcome`

Each observation has an `observed_on` date. Backtests may only use evidence that was publicly knowable by the historical cutoff. A physical completion that happened in March but was only disclosed in June becomes training-eligible in June, not March.

Coarse public dates are retained as intervals (`month`, `quarter`, `half-year`, `year`) instead of being silently converted to fake exact days.

## Product architecture

```text
Primary/public evidence
        │
        ▼
Append-only Event Ledger ──► provenance / conflict / revision checks
        │
        ├──► Evidence Graph + project dossier
        ├──► Physical dependency depth
        ├──► Coverage Snapshot + research priorities
        ├──► Leakage-safe training / hazard exports
        ├──► Walk-forward baselines + interval calibration
        ├──► Model-risk publication policy
        ├──► Decision Card
        └──► FastAPI / SQLite serving layer
```

The dependency-aware Monte Carlo underwriting engine remains available for structured project fixtures, but empirical public-data probabilities are deliberately gated separately.

## Quick start

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[api,dev]"
pytest -q
```

Inspect the public evidence corpus:

```bash
proofmw dataset-snapshot data/europe-public-events-v2 --as-of 2026-08-19
proofmw data-quality data/europe-public-events-v2
proofmw calibration-readiness data/europe-public-events-v2
proofmw model-risk data/europe-public-events-v2
proofmw conditional-benchmark data/europe-public-events-v2 --min-history 5
proofmw research-priorities data/europe-public-events-v2
```

Open a lender-facing project view:

```bash
proofmw project-dossier data/europe-public-events-v2 start-campus-sines --as-of 2026-08-19
proofmw decision-card data/europe-public-events-v2 start-campus-sines --as-of 2026-08-19
```

Build a query index:

```bash
proofmw index-ledger data/europe-public-events-v2 --output build/proofmw.sqlite
proofmw query-index build/proofmw.sqlite --country Portugal --limit 10
```

Run the product:

```bash
uvicorn proofmw.api:app --reload
# open http://127.0.0.1:8000
```

Or with Docker:

```bash
docker build -t proofmw .
docker run --rm -p 8080:8080 proofmw
```

## HTTP surface

Core endpoints:

- `GET /health` — process liveness.
- `GET /ready` — service mode, dataset status, model-risk state and ledger hash.
- `GET /v1/data/snapshot?as_of=YYYY-MM-DD` — dated coverage statement.
- `GET /v1/data/readiness` — hard corpus gates.
- `GET /v1/data/calibration` — interval-aware walk-forward calibration.
- `GET /v1/data/conditional-benchmark` — out-of-time benchmark comparison.
- `GET /v1/data/model-risk` — publishability policy.
- `GET /v1/data/physical-depth` — physical evidence coverage.
- `GET /v1/data/research-priorities` — highest-value missing evidence.
- `GET /v1/projects` — project registry derived from the ledger.
- `GET /v1/projects/{id}/dossier` — evidence chronology.
- `GET /v1/projects/{id}/decision-card` — lender diligence card.
- `GET /v1/search?...` — filter evidence observations.
- `POST /v1/underwrite` — dependency-aware structured-project simulation.

## Dataset: what “complete” means here

ProofMW does **not** claim that a public dataset is universally complete. Private EPC schedules, transformer purchase orders, grid agreements, lender reports and incident records are frequently unavailable.

Instead, every build can emit a `ProofMW Coverage Snapshot v1` containing:

- exact ledger SHA-256;
- evidence and physical-actual time span;
- projects/operators/countries/sources;
- source concentration and provenance;
- resolved, delayed, early/on-time and terminal-negative labels;
- unresolved, overdue and stale forecasts;
- physical-depth coverage;
- hard readiness gates.

That makes “coverage” measurable, diffable and reproducible.

The exact current counts are intentionally **not hard-coded in this README**. Run the snapshot command or inspect the CI artifact; that artifact is the source of truth for the build.

## Model policy

The empirical layer follows a strict rule:

1. reconstruct the historical information set;
2. benchmark against simple alternatives;
3. calibrate out of time;
4. require sufficient sample size and diversity;
5. publish a confidence level only if its independent model-risk gate passes.

The conditional model introduced in V0.5 is therefore a **challenger benchmark**, not an automatically promoted production model.

## Non-negotiable guardrails

- No future evidence in historical features.
- No MVA→MW conversion without an explicit engineering basis.
- No fake exact day when a source only gives month/quarter/year.
- No silent overwrite of contradictory first-party statements.
- No missing evidence interpreted as failure or success.
- No confidence label promoted merely because the code can calculate it.
- JSON evidence shards remain canonical; generated databases are rebuildable artifacts.
- ProofMW is not, by itself, a credit opinion, engineering certification, legal opinion or insurance determination.

## Current path to production

The remaining moat is primarily **data and validation**, not another dashboard:

1. grow resolved forecast→actual histories and rare negative outcomes;
2. replicate deep physical mapping beyond Sines;
3. obtain private lender/EPC/operator ground truth to test public-evidence bias;
4. demonstrate out-of-time lift and calibration;
5. run decision pilots with lenders/insurers/infrastructure investors;
6. only then graduate quantitative outputs from `EVIDENCE_ONLY`.
